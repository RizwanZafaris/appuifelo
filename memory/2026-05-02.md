## What Was Built

### Backend (NestJS)
- **Abstract `PayoutProvider` base class** — uniform interface for all providers
- **7 provider adapters** implementing the base class:
  - `PaymobProvider` — OAuth2 token refresh, `/disbursement` endpoint
  - `SamsaraProvider` — HMAC signature generation, full remittance flow (GetEXRate → SendTransaction)
  - `KhaltiProvider` — API Key header, `/fund/load/` and `/fund/loadstatus/`
  - `SafepayRaastProvider` — Secret key header, RAAST IBAN payouts, title fetch
  - `EightBProvider` — HMAC with service_id + secret_key, card payouts
  - `HrcUblProvider` — OAuth token + SOAP XML envelopes for FundTransfer and GetStatus
  - `HabibMetroProvider` — OTP token flow, COC/fin-transaction/LFT/IBFT
- **ProviderFactory** — loads configs from DB, hot-reloads on change, maps providerCode → adapter
- **Database schema** (Drizzle ORM):
  - `remittance_providers` — credentials (JSONB encrypted at rest), auth type, corridors, currencies, methods
  - `remittance_routes` — corridor, source/target currency, provider, fee, FX markup, min/max, ETA
  - `remittance_transactions` — full audit trail with provider raw responses
- **REST API endpoints**:
  - `GET /remittance/routes?corridor=AE-PK` — list available routes
  - `POST /remittance/quote` — get FX quote with fee breakdown
  - `POST /remittance/send` — initiate payout
  - `GET /remittance/transactions` — list user transactions
  - `GET /remittance/transactions/:id/status` — poll provider status
  - `POST /remittance/webhook/:providerCode` — receive provider webhooks
- **Admin API endpoints**:
  - `GET|POST|PUT|DELETE /admin/remittance/providers` — CRUD providers
  - `POST /admin/remittance/providers/:id/validate` — test credentials
  - `GET|POST|PUT|DELETE /admin/remittance/routes` — CRUD routes
  - `GET /admin/remittance/transactions` — view all transactions

### Portal (Next.js)
- **Remittance Ops Dashboard** (`/remittance-ops`)
  - Providers tab: list all providers with enable/disable toggle, credential validation button
  - Routes tab: table view of all corridors with fee/FX/ETA
  - Transactions tab: placeholder for transaction history
- **Provider Form** (`/remittance-ops/providers/[id]`)
  - Dynamic credential fields based on provider type (7 different forms)
  - Pre-filled default URLs per provider
  - Corridor/currency/method selection with badges
  - Credentials marked as "encrypted at rest"
- **Route Form** (`/remittance-ops/routes/[id]`)
  - Corridor selection with common presets
  - Provider dropdown filtered by availability
  - Payout method dropdown filtered by provider capabilities
  - Fee (bps), FX markup (bps), min/max amount, ETA, priority

## Key Design Decisions

1. **Credentials in portal only** — stored in `remittance_providers.credentials` (JSONB), never in env files or source code
2. **Provider abstraction** — each provider has its own adapter class; adding a new provider = add one file
3. **Hot reload** — `ProviderFactory.reloadProviders()` fetches from DB; admin changes take effect immediately
4. **Route-based routing** — corridor + payout method determines which provider handles the payout
5. **Transaction audit trail** — every provider response stored as JSONB for debugging
6. **Webhook + polling** — providers push status via webhook; fallback polling via `/status` endpoint
